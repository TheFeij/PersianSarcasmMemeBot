A small **Telegram bot running on Telegram's serverless platform** (the `tgcloud`
runtime). It is **currently deployed and in use by the Telegram channel
[PersianSarcasm](https://t.me/PersianSarcasm)**.

The bot serves two purposes:

1. **Channel-post guard** — in the channel's linked discussion group, any post
   forwarded from the channel that does **not** contain a configured phrase is
   automatically deleted.
2. **Report / contact relay** — group members can reply to any message with
   `گزارش` (report) to forward it to a debug/owner chat, or `ادمین` (admin) to
   send a message to the owner.

## How it works

Telegram delivers every update to `handlers/message.js`, which routes the payload
based on what kind of message it is:

| Input in the discussion group            | Handler            | Behaviour                                                        |
|------------------------------------------|--------------------|------------------------------------------------------------------|
| Auto-forwarded channel post              | `lib/guard.js`     | Deletes the post unless its text/caption contains the phrase.    |
| A reply whose text is exactly `گزارش`    | `lib/relay.js`     | Forwards a report (link, sender, group, excerpt) to the debug chat. |
| A reply whose text is exactly `ادمین`    | `lib/relay.js`     | Forwards a message to the owner.                                |
| A command / anything from the owner      | `lib/owner.js`     | Handles owner commands and settings changes.                     |
| Anything else                            | —                  | Ignored.                                                         |

## Owner commands

These only work for the `ownerTGID` configured in `lib/config/config.js`:

| Command               | Description                                                          |
|-----------------------|----------------------------------------------------------------------|
| `/start`, `/help`     | Show setup and usage instructions.                                   |
| `/status`             | Show the current owner, group, and phrase.                           |
| `/setgroup`           | Register the current group (must be sent inside the discussion group; bot must be admin with Delete Messages permission). |
| `/setphrase <phrase>` | Set the phrase required in channel posts.                            |
| `/debug` / `/nodebug` | Turn debug echo messages on/off.                                     |
| `/reset`              | Clear the configured group and phrase.                               |

## Setup

1. Add the bot to the channel's discussion group as an admin with the
   **Delete Messages** permission.
2. Send `/setgroup` inside that group.
3. Send `/setphrase <phrase>` (from the owner account) to set the required phrase.
4. Optionally send `/debug` to receive debug echoes.

## Development & deployment

This project has no server to run locally and no runtime `node_modules`. Modules
import each other by bare name (`import { echo } from 'lib/debug'`), and the only
runtime dependencies are the platform `sdk` and other project modules.

The CLI is a local dev-dependency, so run it through `npm run` or `npx tgcloud`:

```bash
npm run status      # show what changed locally vs the cloud
npm run deploy      # deploy modules (tgcloud push)
npm run migrate     # apply schema.js changes to the database
npm run run -- <module> [args]   # execute a handler server-side
npx tgcloud webhook # inspect the bot's webhook
npx tgcloud pull    # bring the local project in line with the cloud
```

Deploying never touches the database — schema changes are only applied by
`npm run migrate`. After editing `schema.js`, run `migrate` to apply it.

See [AGENTS.md](AGENTS.md) for the platform's rules and gotchas, and
[docs/tgcloud-sdk.md](docs/tgcloud-sdk.md) for the full SDK reference.
