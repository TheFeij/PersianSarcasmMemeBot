# PersianSarcasmMemeBot

> **Note:** This document was generated by an AI coding assistant. It reflects the
> state of the source code, not the author's own words. Treat it as documentation,
> not as a personal statement from the maintainer.

A small **Telegram bot running on Telegram's serverless platform** (the `tgcloud`
runtime). It is **currently deployed and in use by the Telegram channel
[PersianSarcasm](https://t.me/PersianSarcasm)** — a channel with **over 100k
subscribers**. It is used to manage the channel's linked discussion group and to
gather reports on the channel's statistics.

The bot serves these purposes:

1. **Channel-post guard** — in the channel's linked discussion group, any post
   forwarded from the channel that does **not** contain a configured phrase is
   automatically deleted. this feature prevents ads to be in the discussion group
2. **Report / contact relay** — group members can reply to any message with
   `گزارش` (report) to forward it to a debug/owner chat, or `ادمین` (admin) to
   send a message to the owner.
3. **Channel statistics reports** — collects and relays reports on the channel's
   statistics.
4. **Channel post buttons** — the owner can attach inline URL buttons (with an
   optional color) to channel posts. The bot edits the post to add the keyboard.
   Buttons can be applied automatically to every new channel post, or to one
   specific post on demand.
5. **Pattern pinning** — each channel can have a pattern; any new channel post
   whose text or caption contains it is pinned automatically.

## How it works

The bot manages **any number of channels**. Each channel has its own linked
discussion group, guard phrase, default buttons and membership statistics. A
channel is registered automatically when the bot is added to it as an admin (or
when it sees a post there); the legacy single-channel settings are imported once
on the first run after upgrading.

Telegram delivers every update to `handlers/message.js`, which routes the payload
based on what kind of message it is:

| Input in the discussion group            | Handler            | Behaviour                                                        |
|------------------------------------------|--------------------|------------------------------------------------------------------|
| Auto-forwarded channel post              | `lib/guard.js`     | Deletes the post unless its text/caption contains the phrase of that channel. |
| A reply whose text is exactly `گزارش`    | `lib/relay.js`     | Forwards a report (link, sender, group, excerpt) to the debug chat. |
| A reply whose text is exactly `ادمین`    | `lib/relay.js`     | Forwards a message to the owner.                                |
| A command / anything from the owner      | `lib/owner.js`     | Handles owner commands and settings changes.                     |
| A channel post in any channel            | `lib/buttons.js`, `lib/pin.js` | Adds that channel's configured inline buttons (if enabled) and pins the post when it matches the channel's pin pattern. |
| A user joins/leaves a channel            | `lib/members.js`   | Records the join/leave for that channel's report.                |
| The bot is added to/removed from a channel | `lib/channels.js` | Registers/deactivates the channel.                              |
| Anything else                            | —                  | Ignored.                                                         |

Inline-keyboard presses arrive at `handlers/callback_query.js`, which routes
the ads management actions (`a:…` callback data) to `lib/ads.js`.

## Owner commands

These only work for the `ownerTGID` configured in `lib/config/config.js` —
except the ads commands (`/setadd`, `/ads`, `/postad`), which also work for the
extra `adminTGID` configured there.

A channel is referenced as `@username` or its numeric chat id (e.g.
`-1001234567890`). When the command is sent inside a channel's discussion group,
or when exactly one channel is registered, the channel can be omitted.

| Command               | Description                                                          |
|-----------------------|----------------------------------------------------------------------|
| `/start`, `/help`     | Show setup and usage instructions.                                   |
| `/status [channel]`   | List every channel and its config, or show one channel in detail.    |
| `/channels`           | Alias for `/status`.                                                 |
| `/setgroup [channel]` | Register the current discussion group (must be sent inside the group; bot must be admin with Delete Messages permission). The linked channel is detected automatically. |
| `/setphrase [channel] <phrase>` | Set that channel's required phrase.                        |
| `/setpin [channel] <pattern>` | Pin new posts of that channel whose text or caption contains the pattern. |
| `/clearpin [channel]` | Stop pinning matching posts for that channel.                        |
| `/report <channel\|all> [hours\|today]` | Member stats for one channel, or a short summary of all channels. Defaults to `today`. |
| `/reportx <channel a> <channel b>` | How many members of channel a are also members of channel b (tracked members only). |
| `/reportlive <channel a> <channel b> [limit] [offset]` | Same question, but checks each tracked member of channel a against channel b live through the Telegram API. Bounded by `limit` (default 200) and a time budget; rerun with `offset` to continue. |
| `/buttons [channel] [on\|off\|set\|show\|clear]` | Manage that channel's default post buttons. |
| `/post [link]`        | Attach buttons to one specific post (forward it or paste a t.me link). |
| `/deletepost <link>`  | Delete the channel post itself by its t.me link (or by replying to a forwarded copy). Telegram removes the linked discussion auto-forward as a side effect. Requires Delete Messages permission in the channel. |
| `/setadd`, `/setad`   | Schedule an ad with a guided multi-step flow: channel → date (Gregorian) → preceding post → banner → pin → reply. |
| `/ads`                | Manage scheduled ads with inline buttons: edit any field, toggle pin, post now, delete. |
| `/postad [YYYY-MM-DD]` | Post the ad scheduled for that date (default: today in the ad timezone, UTC+3:30). With several ads on one date, choose one from buttons. |
| `/sendadd <channel> [today]` | Post that channel's ad for today (same as `/postad` with today's date, limited to the channel named by `@username` or numeric id). |
| `/previewad [YYYY-MM-DD]` | Play the ad's whole sequence in the debug chat without touching the channel or marking it posted. |
| `/cancel`             | Abort the current multi-step button flow.                            |
| `/debug` / `/nodebug` | Turn debug echo messages on/off.                                     |
| `/reset [channel]`    | Clear that channel's group, phrase, pin pattern and buttons.         |
| `/migrate`            | Copy legacy single-channel settings and member rows into the new tables (also runs automatically). |

### Channel post buttons

Requires the bot to be an admin in the channel with the **Edit Messages of
Others** permission. Buttons are stored per channel.

Define buttons one per line in this syntax:

```
row | color | text | link
```

Example:

```
1 | success | Subscribe | https://t.me/PersianSarcasm
1 | danger  | Contact   | https://t.me/example
2 | primary | Website   | https://example.com
```

Buttons sharing a `row` number appear side by side. `color` is one of
`danger`, `success`, `primary` (or `default`, and aliases `red`, `green`,
`blue`).

- `/buttons <channel> set` starts a flow: the next message you send (the lines
  above) becomes that channel's default set. `/buttons <channel> on` then
  applies it to every new post in the channel.
- `/post` starts a flow to target one post: forward the post or send its
  `https://t.me/...` link, then send the button lines. The bot edits that post
  immediately.

## Ads

Ads are scheduled per channel and posted on demand with `/postad` (or
`/sendadd <channel>` for a specific channel's ad for today).

An extra admin id (`adminTGID` in `lib/config/config.js`) can use the whole ads
section — `/setadd`, `/ads`, `/postad`, `/sendadd`, `/previewad`, `/cancel` and
every management button.
The admin's `/start`/`/help` lists only those commands; any other command from
the admin is silently ignored (no reply at all). Ads and drafts are shared, but
the in-progress draft is per user, so the owner and the admin can each have
their own flow without stepping on each other.

Anyone else who starts or messages the bot gets no reply — the bot only answers
the owner and the ad admin.

`/setadd` walks through, in order:

1. **Channel** — picked from inline buttons (skipped automatically when only
   one channel is registered).
2. **Date** — the next 10 days (today included) are shown as inline buttons
   labelled like `november 23`; you can also type any Gregorian `YYYY-MM-DD`.
3. **Preceding post** — an optional normal post that goes immediately before
   the banner. Send it to the bot as any message (text, photo, video, …) or
   press **Skip**.
4. **Banner** — required; send it to the bot as any message.
5. **Pin** — inline Yes/No: pin the banner in the channel.
6. **Reply** — optional text posted under the banner, or **Skip**.

Both content steps store the message(s) you sent; at posting time the bot
copies a single message with `copyMessage`, and a multi-media album with
`sendMediaGroup`. Media, captions, entities and formatting are preserved.
Albums arrive as several separate updates, but the bot captures every member
automatically — just send the album and it moves straight on to the next step.
Keep those messages in the bot chat — deleting them breaks posting.

`/previewad` (or the **👁 Preview** button on an ad) plays the entire sequence
— preceding post, banner, pin and reply — in the debug chat so you can check it
before it goes to the channel. It does not mark the ad as posted.

`/ads` lists every ad as inline buttons. Selecting one opens its details, from
which you can change the date, channel, preceding post, banner or reply text,
toggle the pin, preview it, post it now, or delete it. The detail view shows how
many items each part has (e.g. `Banner: 4 items`). This is how the preceding
post can be added or replaced after the ad was created.

`/postad` uses today's date in the configured ad timezone (UTC+3:30, set by
`adTimezoneOffsetMinutes` in `lib/config/config.js`) when none is given.
Posting is manual: the ad is not sent automatically, `/postad` is what actually
publishes it. If several ads share the date, the bot shows buttons to choose
one.

Posting order is: preceding post → banner → pin (if set) → reply text (if
set). Telegram channels do not support replies to a post, so if the reply is
rejected the text is posted as a normal message instead.

## Setup

For each channel:

1. Add the bot to the channel as an admin with the **Edit Messages of Others**
   and **Pin Messages** permissions. The channel is registered automatically.
2. Add the bot to the channel's discussion group as an admin with the
   **Delete Messages** permission.
3. Send `/setgroup` inside that group (the linked channel is detected
   automatically).
4. Send `/setphrase <phrase>` inside the group, or
   `/setphrase @channel <phrase>`, to set the required phrase.
5. Optionally send `/setpin @channel <pattern>` so new posts containing that
   text are pinned, and `/debug` to receive debug echoes.

Then check `/status` — it lists every registered channel with its group,
phrase, buttons and tracked member count. `/report @channel 24` gives that
channel's stats.

## Upgrading from the single-channel version

1. `npm run deploy` — deploy the new code.
2. `npm run migrate` — creates the `channels` and `channel_members` tables.
3. Send `/migrate` to the bot (or just run `/status`) — the old settings row is
   copied into `channels`, and every row of the old `members` table is copied
   into `channel_members`. The copy is idempotent (`INSERT OR IGNORE`), so it is
   safe to run more than once. It also happens automatically on the first
   membership update or report if you forget the command.
4. Old tables (`settings` legacy columns, `members`) are left untouched, so the
   history stays available; nothing writes to them any more.

## Development & deployment

This project has no server to run locally and no runtime `node_modules`. Modules
import each other by bare name (`import { echo } from 'lib/debug'`), and the only
runtime dependencies are the platform `sdk` and other project modules.

The CLI is a local dev-dependency, so run it through `npm run` or `npx tgcloud`:

```bash
npm run status      # show what changed locally vs the cloud
npm run deploy      # deploy modules (tgcloud push)
npm run migrate     # apply schema.js changes to the database
npm run run -- <module> [args]   # execute a handler server-side
npx tgcloud webhook # inspect the bot's webhook
npx tgcloud pull    # bring the local project in line with the cloud
```

Deploying never touches the database — schema changes are only applied by
`npm run migrate`. After editing `schema.js`, run `migrate` to apply it.

See [AGENTS.md](AGENTS.md) for the platform's rules and gotchas, and
[docs/tgcloud-sdk.md](docs/tgcloud-sdk.md) for the full SDK reference.
